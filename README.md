# iTools — VK Smart Publisher

Local-first PWA для Android (Chrome): массовая загрузка записей ВКонтакте по ссылкам, отдельный редактор для каждой записи,
общий Checkbox ссылок авторов, индивидуальное время публикации, общий предпросмотр и публикация в свой аккаунт ВКонтакте
через официальный VK API. Без платного сервера и облачной базы данных — все данные хранятся на устройстве.

**Инструменты «Топ товаров»** (Главная → карточки инструментов, адрес `#/top`):
1. **Топ товаров Садовода** — поиск открытых сообществ и продавцов во ВКонтакте (`groups.search`, быстрые запросы
   «Садовод», «Садовод рынок», «Садовод опт»…), сохранение их как источников и рейтинг самых популярных записей-товаров.
2. **Топ товаров аккаунтов** — добавьте любые страницы людей и сообществ ВКонтакте по ссылкам (любое количество),
   iTools найдёт их лучшие товары.

Рейтинг: общий балл `(лайки + 3×репосты + 2×комментарии + просмотры/50) × свежесть`, свежесть `1/(1 + дни/30)`;
сортировка также по лайкам, репостам, комментариям, просмотрам, вовлечённости. Период 7/30/90/365 дней, глубина
100/300/500 записей на источник, «только записи с фото», реклама исключается, одинаковые репосты считаются один раз,
цена извлекается из текста. Выбранные товары одной кнопкой попадают в VK Publisher (без повторной загрузки).
Источники и последние результаты хранятся в IndexedDB и доступны офлайн; входят в резервную копию.

**«Поделиться» → iTools** (Web Share Target): из любого приложения Android (например, ВКонтакте) ссылки из присланного
текста попадают в поле VK Publisher.

**Какие права нужны** (проверено по dev.vk.com, ноябрь 2026): `wall.get`, `wall.getById`, `groups.search`,
`groups.getById`, `users.get`, `utils.resolveScreenName` работают с обычным ключом пользователя — **письмо в поддержку
не нужно** для загрузки записей и «Топ товаров». Только `wall.post` (публикация) требует право `wall`, которое VK выдаёт
«в исключительных случаях» по запросу на devsupport@corp.vk.com, для ключа Standalone-приложения (Implicit Flow).
По умолчанию iTools запрашивает только `vkid.personal_info`; расширенные доступы включаются в Настройках.

**Стек:** React 19.3 · Vite+ 1.7 (`vp`: Vite 8, Vitest 5, Oxlint) · IndexedDB · Service Worker · Web App Manifest · JavaScript ES Modules.

## 2. Запуск

Нужен Node.js 20+ (проверено на Node 26).

### Локально на компьютере (основной способ, без GitHub)

Дважды щёлкните **`start-itools.cmd`** в папке проекта. При первом запуске он установит зависимости, затем соберёт
приложение и откроет **http://localhost/** в браузере. Окно с сервером не закрывайте, пока пользуетесь iTools
(остановка — Ctrl+C). То же из терминала:

```bash
npm run local
```

Почему порт 80: VK ID для локального входа разрешает только `http://localhost` (порт 80) и `https://localhost` (443).
В кабинете VK ID укажите базовый домен `localhost` и доверенный redirect URL `http://localhost/`.
Данные хранятся в браузере компьютера (IndexedDB) отдельно для адреса `http://localhost`: публикации, история и
источники с сайта на GitHub Pages сюда не переносятся — используйте экспорт/импорт резервной копии.
Если порт 80 занят другой программой (IIS, Skype и т. п.), закройте её.

### Для разработчика

```bash
npm install
```

```bash
npm run dev
```

Откройте http://localhost:5173. Сборка и проверка production-версии (с Service Worker):

```bash
npm run build
```

```bash
npm run preview
```

Тесты и линтер:

```bash
npm test
```

```bash
npm run lint
```

Открыть dev-сервер с телефона в той же Wi-Fi сети: `npm run dev` показывает адрес `Network: http://192.168.x.x:5173`.
Офлайн-режим и установка требуют HTTPS, поэтому полноценно проверяйте на хостинге (раздел 3).

## 3. Размещение в интернете (необязательно, для телефона)

Локальный сервер работает только на этом компьютере. Чтобы установить iTools на Android, нужен HTTPS-адрес.

**GitHub Pages (только вручную):** автоматический запуск отключён. Чтобы обновить сайт, откройте
GitHub → Actions → **Deploy iTools to GitHub Pages** → **Run workflow**. Workflow прогонит тесты, соберёт и опубликует
`https://<логин>.github.io/<репозиторий>/` (Settings → Pages → Source: GitHub Actions).

**Альтернативы:** Cloudflare Pages / Netlify / Vercel — команда сборки `npm run build`, папка публикации `dist`.
Настраивать перенаправления не нужно: используется hash-роутер, пути относительные (`base: './'`).

## 4. Установка на Android

1. Откройте адрес сайта в **Google Chrome** на телефоне.
2. На Главной нажмите **«Установить»** (или меню Chrome ⋮ → «Установить приложение» / «Добавить на главный экран»).
3. iTools появится на главном экране и будет открываться как отдельное приложение со своим Splash Screen.
4. После первого открытия приложение работает без интернета (редактирование, предпросмотр, черновики, история, время, экспорт/импорт).
5. В Настройках нажмите «Защитить данные от очистки» — браузер не удалит IndexedDB при нехватке места.

## 5. Настройка VK API (обязательно для загрузки и публикации)

Сверено с официальной документацией VK ID (id.vk.ru, ноябрь 2026).

1. Войдите в кабинет сервиса авторизации VK ID (https://id.vk.ru, документация: https://id.vk.ru/about/business/go/docs)
   → **Мои приложения → Добавить приложение**, платформа **Web**.
   Вход в кабинет — через VK Бизнес ID; профиль бизнеса нужно подтвердить (иначе приложение заблокируют через 60 дней,
   а расширенные доступы недоступны).
2. **Базовый домен:** домен хостинга, например `<логин>.github.io`.
3. **Доверенный redirect URL:** точный адрес приложения, например `https://<логин>.github.io/<репозиторий>/`
   (со слешем в конце, без `#`). Тот же адрес показан в iTools на странице «Мой аккаунт».
   Для локальной проверки VK ID разрешает только `http://localhost` (порт 80) и `https://localhost` (443) — порт 5173 не подойдёт.
4. **Ключи доступа → Уровень конфиденциальности: Публичное.** iTools обменивает код на токен в браузере по PKCE;
   «Защищённый ключ» и «Сервисный ключ» в приложение **не вставляйте** — они не нужны и не должны попадать в JavaScript.
5. **Доступы.** По умолчанию iTools запрашивает только базовый `vkid.personal_info` — этого достаточно для входа,
   загрузки записей по ссылкам и «Топ товаров». Для публикации нужны `wall` (+ `photos`, `video` для вложений) —
   это **расширенные доступы**, VK выдаёт их по запросу на devsupport@corp.vk.com с обоснованием. Когда выдадут,
   включите в iTools: Настройки → «Запрашивать расширенные доступы» и подключите аккаунт заново.
6. Скопируйте **ID приложения** и введите его в iTools: Настройки → Приложение ВКонтакте (или переменная `VITE_VK_APP_ID`).
7. «Мой аккаунт ВКонтакте» → **Подключить ВКонтакте** → подтвердите доступ → «Проверить подключение».

Запасной режим «Классический OAuth» (Настройки → Способ входа) использует `oauth.vk.com` Implicit Flow для старых
Standalone-приложений. VK перенёс Standalone-приложения в VK ID, поэтому работоспособность этого режима зависит от VK.

## 6. Как это устроено (важные решения)

| Требование | Реализация |
|---|---|
| Одно поле для любых ссылок | `link-parser.js`: разделители — новая строка/пробел/запятая; дубликаты удаляются; ошибки показываются с причиной; лимита нет |
| Загрузка пакетами | `wall.getById` по 100 записей за запрос, очередь ≤3 запроса/с, прогресс и кнопка «Остановить» |
| N ссылок → N редакторов | каждая запись — отдельная строка IndexedDB и отдельный `PostCard`, подписанный только на свою запись |
| Большие списки | виртуализация `@tanstack/react-virtual`: в DOM только видимые карточки |
| Один Checkbox ссылок авторов | ссылка добавляется при формировании итогового текста, а не вписывается в редактор: правки не повреждаются, дублей нет, выключение мгновенно прекращает добавление |
| Сохранение Checkbox | IndexedDB (источник истины) + зеркало в LocalStorage для мгновенной отрисовки |
| Индивидуальное время | дата + часы + минуты на запись, часовой пояс устройства показан явно, прошлое запрещено |
| Отложенная публикация | `wall.post` c `publish_date` — запись уходит в «Отложенные» на сервере ВКонтакте и выходит без телефона |
| Если VK не принял расписание | статус «Требуется действие» + выбор: изменить время / снять время / «Ждать в приложении» с явным предупреждением, что это работает только при открытом приложении |
| Защита от дублей | блокировка повторного запуска; `guid` VK; статус «Публикуется» сохраняется до запроса; при обрыве связи сначала `wall.get` (проверка стены), затем решение |
| Токены | VK ID PKCE, токен зашифрован AES-GCM неизвлекаемым ключом WebCrypto в IndexedDB; в LocalStorage токенов нет; резервные копии токенов не содержат |
| Офлайн | Service Worker: precache всех файлов сборки, навигация network-first с fallback на кэш |

**Почему JSONP для VK API:** `api.vk.com` не разрешает CORS для произвольных сайтов, а JSONP (`callback=`) — официально
поддерживаемый режим. Следствие: запросы идут методом GET, поэтому очень длинные тексты (десятки тысяч символов кириллицы)
могут не пройти — iTools заранее предупредит, если адрес запроса превысит 60 000 символов.

## 8. Что требует дополнительной настройки / не проверено

1. **Сценарий 12 (реальная публикация и отложенная публикация) не проверен** — нужен ваш ID приложения VK ID
   с выданным доступом `wall` и тестовый аккаунт. Проверьте: 1 запись без времени + 1 со временем → во ВКонтакте
   первая на стене, вторая в «Отложенных записях».
2. **Доступ `wall`/`photos`/`video` в VK ID** — расширенный, может потребовать подтверждения бизнес-профиля и запроса в поддержку VK.
3. **Чужие фото/видео во вложениях** прикрепляются по ID (`photo-1_2_accesskey`). Если VK не разрешит прикрепить
   чужой объект, публикация вернёт ошибку; повторная загрузка медиа в ваш альбом не реализована.
4. **Капча ВКонтакте** показывается пользователю для ручного ввода — iTools её не обходит.
5. **Лимиты ВКонтакте** на число отложенных записей в сутки и на частоту публикаций действуют; при превышении запись
   получает статус «Требуется действие» с текстом ошибки VK.
6. **Локальное ожидание** (если VK не принял расписание) срабатывает, только пока iTools открыт: Android может остановить Chrome в фоне.
7. На хостинге рекомендуется заголовок CSP (`script-src 'self' https://api.vk.com; connect-src 'self' https://id.vk.ru`) — на GitHub Pages заголовки не настраиваются,
   на Cloudflare Pages/Netlify — через файл `_headers`.
